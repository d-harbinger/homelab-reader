<objective>
Give every user a settings page to mint, label, list, and revoke their own OPDS
API tokens, backed by REST under the cookie session. The mint endpoint generates
the opaque token, hashes it for storage, and returns the plaintext exactly once
(copy-once UX). Listing never exposes the token or hash; revoke is per-user with
the established by-id ownership 404. This is the human-facing half of OPDS-01
(the credential source) and the copy-once / hashed-at-rest conformance points of
OPDS-04.

Purpose: a user needs a way to obtain the token that android-reader and standard
OPDS clients send, and to revoke it without changing their login password —
exactly as the cross-repo contract describes.

Output: src/app/api/opds-tokens/route.ts, src/app/api/opds-tokens/[id]/route.ts,
src/app/settings/tokens/page.tsx, src/components/TokenManager.tsx, a header nav
link, and a Vitest suite covering mint/list/revoke + per-user isolation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (cookie session) -> /api/opds-tokens | Authenticated user manages credentials; the id in a DELETE path is attacker-supplied. |
| Mint response -> client | The only moment the plaintext token leaves the server. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Elevation of Privilege (IDOR) | DELETE /api/opds-tokens/[id] | mitigate | Ownership check `existing.userId !== userId -> 404` mirroring notes/[id]; a user can revoke only their own tokens, and non-ownership is not leaked (404, not 403). |
| T-02-07 | Information Disclosure | GET /api/opds-tokens list | mitigate | `select` excludes tokenHash; the plaintext token is returned ONLY by POST at mint time, never by GET. |
| T-02-08 | Information Disclosure | token at rest / logs | mitigate | Store sha256 hex only; mint generates randomBytes(32) base64url; never console.log the token or hash. |
| T-02-09 | Spoofing | mint requires session | mitigate | getCurrentUserId() gates mint/list/revoke; signed-out -> 401 via authError. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs — reuses useSWR, lucide-react, node:crypto already in the tree. No legitimacy gate required. |
</threat_model>
