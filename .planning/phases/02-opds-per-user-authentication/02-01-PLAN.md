<objective>
Close the anonymous-OPDS-enumeration gap: stand up the token model, an in-route
auth guard, and enforce it on all three OPDS routes plus a new OPDS-context
progress write. The guard accepts both HTTP Basic and Bearer exactly as the
cross-repo contract pins, hashes tokens at rest, and constant-time-compares the
hash. This plan delivers the server side of OPDS-01, OPDS-02, OPDS-03 and the
conformance core of OPDS-04.

Purpose: standard OPDS readers and android-reader (separate repo, built against
the same contract) must be unable to read the catalog without a per-user token,
and progress reported over that path must land on the right account.

Output: OpdsToken model + migration, src/lib/opds-auth.ts, three guarded OPDS
routes, an OPDS-context progress route, an updated middleware comment, and a
Vitest suite covering accept/reject/attribution.
</objective>

  <files>src/lib/opds-auth.ts, tests/opds-auth.test.ts</files>

  <behavior>
    - Parses Authorization: `Basic base64(username ":" token)` — base64-decode the credential, split on the FIRST colon, the token is the password half (everything after the first colon, so colons in the token survive).
    - Parses Authorization: `Bearer <token>` — token is the remainder after "Bearer ".
    - No Authorization header, or a scheme that is neither Basic nor Bearer -> returns null.
    - Hashes the extracted token with SHA-256 hex, looks up OpdsToken by tokenHash, and on a match returns the owning user (resolved via the FK relation).
    - Constant-time confirm: after the hash lookup, timingSafeEqual the stored hash against the recomputed hash before trusting the row (defense-in-depth per contract).
    - Unknown/wrong token -> returns null.
    - On success, fires a fire-and-forget lastUsedAt bump that does NOT block the return (the caller must not await it).
    - Never logs the token or the hash.
    - opdsChallenge(body?) returns a Response with status 401 and header `WWW-Authenticate: Basic realm="homelab-reader OPDS"`.
  </behavior>
  <action>
Create src/lib/opds-auth.ts. Export `authenticateOpds(req: Request): Promise<User | null>` (return the full user row from the relation; the routes that need only progress attribution use user.id). Use `node:crypto` (`createHash`, `timingSafeEqual`). Parse the Authorization header per the behavior block: branch on the scheme prefix case-sensitively as the contract writes them (`Basic `, `Bearer `). For Basic, base64-decode and split on the first colon only. Hash the token, `prisma.opdsToken.findUnique({ where: { tokenHash }, include: { user: true } })`, then timingSafeEqual the stored vs recomputed hash (equal length so no length-leak branch needed). Fire-and-forget the lastUsedAt bump with `void prisma.opdsToken.update(...).catch(() => {})` — do not await. Also export `opdsChallenge(body = "Authentication required")` returning `new NextResponse(body, { status: 401, headers: { "WWW-Authenticate": 'Basic realm="homelab-reader OPDS"' } })` (import NextResponse from next/server). No code fences in this plan — write the implementation directly in the file. Never console.log the token or hash.

Write tests/opds-auth.test.ts FIRST against the behavior block, mirroring the
tests/isolation.test.ts recipe (vi.hoisted ephemeral PrismaClient +
vi.mock("@/lib/prisma")). Seed a user and an OpdsToken whose tokenHash is the
SHA-256 of a known plaintext. Cases: no header -> null; valid Basic
(base64("alice:" + token)) -> the user; valid Bearer -> the user; wrong token
-> null; malformed header (e.g. "Digest x") -> null; token containing a colon
survives the first-colon split. Assert the returned user.id matches the seeded
owner.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OPDS client -> /api/opds* | Untrusted machine client (any LAN host) sends Authorization header; crosses into the catalog and progress data. |
| Authorization header -> token store | Attacker-controlled bytes used to look up a stored credential hash. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | OPDS routes (anonymous enumeration — the gap this phase closes) | mitigate | authenticateOpds called first in every OPDS GET; null -> 401 + WWW-Authenticate. No feed bytes returned without a valid token. |
| T-02-02 | Spoofing / Tampering | token at rest | mitigate | Store only SHA-256 hex (tokenHash @unique); plaintext never persisted (no plaintext column) and never logged. |
| T-02-03 | Information Disclosure | token lookup timing oracle | mitigate | timingSafeEqual(storedHash, recomputedHash) constant-time confirm after the indexed findUnique. |
| T-02-04 | Elevation of Privilege | progress attribution over OPDS | mitigate | /api/opds/progress uses authenticateOpds(user.id), never the cookie session; a token writes only its owner's Progress row (bookId_userId upsert). |
| T-02-05 | Information Disclosure | Basic over plain HTTP on LAN | accept | Contract: HTTPS strongly recommended; TLS termination is the operator's deployment call, out of this phase's code. Documented, not enforced. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs this plan — node:crypto and existing deps (prisma, next, vitest) only. No legitimacy gate required. |
</threat_model>
