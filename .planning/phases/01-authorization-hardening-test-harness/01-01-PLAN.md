<objective>
Close the two known authorization defects and the scope-adjacent aggregate leak, and promote the duplicated `authError` helper to a single home — without introducing any new wrapper abstraction. This is the code-change half of the phase; Plan 01-02 stands up the tests that lock these behaviors in.

Three fixes, one refactor:
1. AUTHZ-01 — `POST /api/scan` gains the `requireAdmin()` gate it is missing (any reader can currently trigger a full filesystem rescan).
2. AUTHZ-02 — the unguarded `getCurrentUserId()` calls in notes/highlights/progress get wrapped so an expired/absent session returns 401 JSON instead of an unhandled 500.
3. AUTHZ-03 (additional scope, same bug class) — `GET /api/progress/recent` gains a `userId` filter so it stops returning every user's in-progress books.
4. Refactor — `authError(e)` is promoted from its two duplicate definitions into `src/lib/current-user.ts` and reused everywhere.

Purpose: a LAN-exposed multi-user server currently lets any reader rescan the library and leaks one user's "continue reading" list to all. These are live gaps, not hypotheticals.
Output: the ten route/lib files above, edited in place, with no behavior change to the already-correct paths.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/OPDS client → route handler | Untrusted HTTP input (session cookie may be absent, expired, or belong to a non-admin / different user) crosses into the handler. This is where the authorization decision must be made — the edge middleware is only a coarse cookie pre-filter, not the authz decision (per the Architectural Responsibility Map). |
| Route handler → Prisma/SQLite | The handler decides which `userId`-scoped rows the query may touch; a missing scope here is an IDOR. |
