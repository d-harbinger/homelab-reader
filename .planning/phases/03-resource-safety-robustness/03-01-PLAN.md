<objective>
Backend robustness for the homelab container under real concurrent use: SQLite
no longer locks under a reader + background-writer workload, the cold-start
scan can't fan out unbounded, each PDF is read once instead of twice, and a
malformed book is recorded as a visible FailedImport instead of silently
vanishing.

Purpose: This is the highest-leverage half of Phase 3 — WAL + busy_timeout is
the standard "Prisma + SQLite + background writer" fix; the limiter and the
read-once change cap memory; the FailedImport model + scanner recording is the
data layer the next plan's API/UI and tests build on.

Output: applySqlitePragmas helper + call site, connection_limit doc, an
in-house concurrency limiter wired into the watcher, pdf.ts reading once, and
the FailedImport model + hand-written migration + record/clear helpers wired at
the watcher boundary.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → scanner | Third-party EPUB/PDF bytes (untrusted structure) cross into the parser |
| concurrent readers + background writer → single SQLite file | Write contention point |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | SQLite under reader + scanner writer | mitigate | WAL + busy_timeout=5000 PRAGMA at boot, connection_limit=1 on DATABASE_URL serializes writers (ROBUST-01) |
| T-03-02 | Denial of Service | watcher cold-start fan-out | mitigate | createLimiter cap 4 around per-event scanFile dispatch (ROBUST-02) |
| T-03-03 | Denial of Service | PDF double-read RSS spike | mitigate | read each PDF once, pass bytes to cover renderer (ROBUST-04) |
| T-03-04 | Information Disclosure | FailedImport.error message | mitigate | truncate stored message; recordFailedImport stores format + path + bounded error only (full path stays server-side; basename-only surfacing is enforced in Plan 02) |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies added (in-house limiter, pdf-to-img already present); nothing to install, so no supply-chain checkpoint required |
</threat_model>
